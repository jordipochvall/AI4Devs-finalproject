# HU-24 — Despliegue cloud con entrega continua

> **Como** equipo de plataforma,
> **quiero** desplegar la aplicación en un entorno cloud público mediante un pipeline de entrega continua,
> **para** ofrecer un entorno accesible y reproducible más allá de la ejecución local con Docker Compose.

**Contexto y valor.** El MVP solo contempla ejecución local con Docker Compose (decisión diferida D9). Esta historia añade el empaquetado de imágenes, la infraestructura como código, los secretos gestionados y un pipeline de **CD** que promociona a un entorno de *staging* y luego a producción, sobre la base del pipeline de **CI** existente (`HU-1-DEV-01`).

**Prioridad:** Should Have · **Estimación:** L · **Endpoint:** *(infra/CD, sin endpoint)*

## Criterios de aceptación (BDD)

```gherkin
# language: es
Característica: Entrega continua a cloud

  Escenario: Construir y publicar imágenes versionadas
    Cuando se integra un cambio en la rama principal
    Entonces se construyen imágenes de API y web etiquetadas por versión y se publican en un registro

  Escenario: Promoción a staging automática
    Dado imágenes publicadas
    Cuando el pipeline de CD se ejecuta
    Entonces el entorno de staging queda desplegado con migraciones aplicadas y comprobación de salud

  Escenario: Promoción a producción con aprobación
    Dado un staging verde
    Cuando se aprueba la promoción
    Entonces producción se actualiza sin downtime perceptible y con posibilidad de rollback

  Escenario: Configuración y secretos seguros
    Entonces las credenciales (BBDD, JWT, ANTHROPIC_API_KEY) se inyectan desde un gestor de secretos, nunca en la imagen
```

## Verificación INVEST

| Criterio | Cumplimiento |
|---|---|
| **I**ndependiente | Construye sobre la CI existente sin cambiar la aplicación. |
| **N**egociable | El proveedor cloud y la herramienta de IaC son negociables. |
| **V**aliosa | Habilita demos públicas, *staging* realista y operación continua. |
| **E**stimable | IaC + pipeline de CD + gestión de secretos + comprobaciones de salud. |
| **S**mall | Es **L**: divisible (staging primero; producción con aprobación/rollback después). |
| **T**estable | Verificable con despliegues a staging, *smoke tests* post-deploy y un rollback ensayado. |

**Fuera de alcance:** multi-región activo-activo, autoescalado avanzado y DR con RPO/RTO formalizados.
