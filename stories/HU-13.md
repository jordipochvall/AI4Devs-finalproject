# HU-13 — Sesión persistente con refresh tokens

> **Como** usuario de cualquier perfil,
> **quiero** que mi sesión se renueve sin volver a introducir credenciales cuando el token caduca,
> **para** trabajar sin interrupciones manteniendo la seguridad de tokens de vida corta.

**Contexto y valor.** En el MVP el *access token* caduca a la hora y obliga a re-autenticarse (decisión diferida D2). Un *refresh token* de vida más larga permite renovar el acceso de forma silenciosa, mejorando la UX sin sacrificar la rotación frecuente del *access token*.

**Prioridad:** Should Have · **Estimación:** S · **Endpoint:** `POST /auth/refresh`

## Criterios de aceptación (BDD)

```gherkin
# language: es
Característica: Renovación silenciosa de la sesión

  Antecedentes:
    Dado un usuario autenticado con un access token y un refresh token

  Escenario: Renovar el access token antes de que caduque la sesión
    Dado que el access token ha expirado pero el refresh token es válido
    Cuando el cliente solicita la renovación
    Entonces obtengo un nuevo access token sin reintroducir credenciales
    Y la operación que estaba realizando continúa de forma transparente

  Escenario: Refresh token inválido o caducado
    Cuando solicito la renovación con un refresh token caducado o revocado
    Entonces se rechaza con "no autenticado"
    Y se me redirige a la pantalla de inicio de sesión

  Escenario: Cierre de sesión revoca el refresh token
    Cuando cierro sesión
    Entonces el refresh token deja de ser válido para futuras renovaciones
```

## Verificación INVEST

| Criterio | Cumplimiento |
|---|---|
| **I**ndependiente | Se apoya solo en la autenticación existente (HU-4); no toca el dominio de juego. |
| **N**egociable | La estrategia (rotación de refresh, almacenamiento) es negociable; la renovación silenciosa no. |
| **V**aliosa | Elimina re-logins molestos en sesiones largas (matemático simulando, operador auditando). |
| **E**stimable | Alcance acotado: un endpoint + interceptor de cliente + tabla/columna de tokens. |
| **S**mall | Cabe en un sprint corto. |
| **T**estable | Verificable con tokens expirados/revocados y con la renovación automática en el interceptor. |

**Fuera de alcance:** *single sign-on* con proveedores externos (OAuth/OIDC) y gestión de múltiples dispositivos con revocación selectiva.
