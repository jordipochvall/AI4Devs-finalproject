# HU-39 — Un error de render no deja la pantalla en blanco

> **Como** cualquier perfil de usuario del demo,
> **quiero** ver un mensaje de error controlado si algo falla al renderizar,
> **para** no encontrarme una pantalla en blanco sin explicación mientras pruebo la aplicación.

**Prioridad:** Could Have · **Estimación:** S · **Perfil:** Transversal

## Contexto y valor

El frontend (React 18 + TS) **no tiene ningún `ErrorBoundary`**: si un componente lanza una excepción durante el render (un dato inesperado de la API, un caso límite no contemplado), React desmonta el árbol y la SPA se queda en blanco, sin ningún mensaje. Para un demo que van a probar personas ajenas al equipo (evaluadores del proyecto), una pantalla en blanco sin pistas es la peor experiencia posible ante un fallo menor.

## Alcance

- Añadir un `ErrorBoundary` en la raíz de la aplicación (o, como mínimo, envolviendo las rutas principales) que capture errores de render y muestre un mensaje amigable con una acción de recuperación (recargar / volver al inicio), en vez de una pantalla en blanco.
- Registrar el error capturado en consola (o donde ya se centralice el logging del frontend) para poder diagnosticarlo.

## Criterios de aceptación (BDD)

```gherkin
# language: es
Característica: ErrorBoundary global

  Escenario: Un componente lanza una excepción de render
    Dado la aplicación cargada
    Cuando un componente lanza un error durante el render
    Entonces se muestra una pantalla de error legible con una acción de recuperación
    Y el resto de la sesión (autenticación, idioma) no se pierde
```

## Verificación INVEST

| Criterio | Cumplimiento |
|---|---|
| **I**ndependiente | Un componente `ErrorBoundary` envolvente; no cambia la lógica de negocio. |
| **N**egociable | El diseño exacto del mensaje de error es negociable. |
| **V**aliosa | Evita la peor experiencia posible (pantalla en blanco) ante cualquier evaluador del demo. |
| **E**stimable | Un componente + su integración en el árbol raíz. |
| **S**mall | Un componente y su test. |
| **T**estable | Test que fuerza un error de render y verifica que se muestra el *fallback*. |

**Fuera de alcance:** telemetría/reporting de errores a un servicio externo (Sentry, etc.).
