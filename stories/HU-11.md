# HU-11 — El usuario utiliza la plataforma en su idioma (ES/EN)

> **Como** persona usuaria de cualquier perfil,
> **quiero** usar la interfaz en español o en inglés y poder cambiar de idioma,
> **para** trabajar y jugar en la lengua con la que me siento cómoda.

**Contexto y valor.** Recoge la feature [1.2-A9](../readme.md#12-características-y-funcionalidades-principales). Es una capa transversal: el frontend usa i18next (bundles `es`/`en`) y el backend traduce sus mensajes (errores RFC 9457) según la cabecera `Accept-Language`. Afecta a las tres superficies (jugador, operador, matemático).

**Prioridad:** Must Have · **Estimación:** S · **Endpoint:** ninguno propio (cross-cutting; el backend respeta `Accept-Language` en todas las respuestas)

## Criterios de aceptación (BDD)

```gherkin
# language: es
Característica: Internacionalización ES/EN

  Escenario: Idioma por defecto según el perfil del usuario
    Dado un usuario con idioma configurado en español
    Cuando accede a la plataforma
    Entonces todos los textos de la interfaz se muestran en español

  Escenario: Cambio de idioma en caliente
    Dado que estoy usando la interfaz en español
    Cuando cambio el idioma a inglés
    Entonces los textos se actualizan a inglés sin recargar la página

  Escenario: Persistencia de la preferencia de idioma
    Dado que he seleccionado inglés
    Cuando cierro sesión y vuelvo a entrar
    Entonces la interfaz se muestra en inglés

  Escenario: Mensajes del servidor traducidos
    Dado que mi idioma es inglés
    Cuando una operación devuelve un error de validación
    Entonces el mensaje de error se recibe en inglés

  Escenario: Sin textos sin traducir
    Cuando navego por las superficies de jugador, operador y matemático en inglés
    Entonces no aparece ningún texto en español ni claves de traducción sin resolver
```

## Verificación INVEST

| Criterio | Cumplimiento |
|---|---|
| **I**ndependiente | La infraestructura i18n (i18next + `MessageSource`) se monta de forma autónoma; cada pantalla consume las claves. |
| **N**egociable | El conjunto de idiomas es negociable (la arquitectura admite añadir más); ES/EN es el alcance acordado. |
| **V**aliosa | Habilita el público hispano y la internacionalización B2B; fue una decisión firme de producto. |
| **E**stimable | Setup de i18next + bundles + `MessageSource`; alcance acotado. |
| **S**mall | Pequeña como infraestructura; el coste recurrente es mantener las claves al crear pantallas. |
| **T**estable | Verificable con tests de UI (conmutación y persistencia) y de API (mensajes según `Accept-Language`). |

**Fuera de alcance:** idiomas adicionales más allá de ES/EN; localización de formatos de moneda/fecha más allá de lo necesario para ES/EN.
