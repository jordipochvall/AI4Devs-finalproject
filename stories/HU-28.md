# HU-28 — Sistema de diseño y tipografía coherentes en toda la app

> **Como** responsable de producto (y en beneficio de todos los perfiles: jugador, operador, matemático y admin),
> **quiero** que toda la interfaz comparta una tipografía, una paleta y unos componentes coherentes,
> **para** que el producto se perciba profesional y consistente, y para poder evolucionar el estilo desde un único sitio.

**Contexto y valor.** Una auditoría de usabilidad detectó que no existía una capa de diseño global: `index.html` no cargaba ninguna fuente y varias pantallas (juego, dashboard, historial, límites, replay, auditoría) heredaban la fuente serif por defecto del navegador mientras otras usaban `system-ui`; los colores estaban hardcodeados con dos "dorados" distintos; y componentes como botones, campos y diálogos se redefinían en cada CSS. Esta historia introduce **tokens de diseño**, **fuentes web auto‑alojadas** y un **catálogo de componentes** único, y migra el CSS existente para consumirlos. Documentado en [§5](../readme.md#5-especificaciones-de-frontend).

**Prioridad:** Should Have · **Estimación:** M · **Perfil:** Transversal (plataforma)

## Criterios de aceptación (BDD)

```gherkin
# language: es
Característica: Sistema de diseño coherente

  Escenario: Tipografía unificada
    Dado cualquier pantalla de la aplicación (jugador o backoffice)
    Cuando se renderiza
    Entonces el cuerpo usa la fuente sans (Inter) y los títulos la serif display (Cinzel)
    Y ninguna pantalla queda con la fuente serif por defecto del navegador

  Escenario: Fuentes servidas same-origin (CSP)
    Dado que la CSP de nginx es "default-src 'self'"
    Cuando el navegador solicita las fuentes
    Entonces se sirven desde "/fonts/*.woff2" del mismo origen, sin bloqueos de CSP

  Escenario: Tokens de color y componentes
    Dado un botón primario, un campo o un diálogo en dos superficies distintas
    Entonces se ven idénticos porque provienen del catálogo común
    Y sus colores derivan de tokens (un único dorado de marca)

  Escenario: Contraste accesible
    Dado un texto secundario/tenue sobre el fondo oscuro
    Entonces su contraste cumple WCAG 2.1 AA
```

## Verificación INVEST

| Criterio | Cumplimiento |
|---|---|
| **I**ndependiente | Capa de estilos transversal; no depende de lógica de negocio. |
| **N**egociable | La elección concreta de familias tipográficas y paleta es negociable. |
| **V**aliosa | Coherencia de marca y mantenibilidad (estilo cambiable desde tokens). |
| **E**stimable | Tokens + fuentes + componentes + migración de CSS. |
| **S**mall | Acotada a estilos; sin cambios de marcado salvo utilidades. |
| **T**estable | `vitest` + `tsc` en verde; revisión visual de tipografía/contraste. |

**Fuera de alcance:** rediseño de flujos o de la disposición de cada pantalla (más allá de estilos comunes); animaciones de juego (HU-30).
