# HU-32 — "Ask the AI" funcional (con modo offline sin API key)

> **Como** matemático,
> **quiero** poder preguntar en lenguaje natural sobre una simulación completada y recibir una respuesta útil,
> **para** interpretar las métricas sin depender de tener contratada una API de IA.

**Prioridad:** Should Have · **Estimación:** M · **Perfil:** Matemático

**Contexto y valor.** La caja de preguntas a la IA (`ExplainBox`, HU-8) ya existe en la UI, pero **hoy no funciona**: el adaptador Anthropic sólo se instancia con `anthropic.enabled=true` y `docker-compose` **no pasa `ANTHROPIC_ENABLED`** al contenedor, así que el endpoint responde **503** y la caja se muestra como "no disponible". Además, no siempre se dispone de una **API key** de Anthropic (sólo hay crédito de prueba variable). Esta historia hace que "ask the AI" sea **funcional de serie** mediante un **modo offline** determinista, y deja **lista la activación real de Claude** para cuando haya key.

## Alcance

1. **Explainer local (offline) determinista** como *fallback* cuando no hay key: en lugar de 503, el endpoint devuelve una explicación **generada a partir de las métricas de la simulación** (RTP y su intervalo, comparación con el target, hit-frequency, volatilidad, frecuencia de free-spins, descomposición por símbolo…). Reutiliza el puerto `Explainer` (`nova-domain/ai`) y el patrón `FakeExplainer` ya presente en los ITs.
2. **Activación real de Claude:** `docker-compose` pasa `ANTHROPIC_ENABLED`; `.env.example` documenta `ANTHROPIC_ENABLED` / `ANTHROPIC_API_KEY` / `ANTHROPIC_MODEL` (con un **id de modelo válido**); los errores del proveedor (key inválida, rate limit, etc.) **degradan a 503** sin romper el resto del panel.
3. **Frontend:** sin cambios de superficie (la caja `ExplainBox.tsx` y el historial `/explanations` ya existen); a lo sumo, ajustar el copy para el modo offline.

> **Cómo obtener una API key (opcional).** Alta en la Anthropic Console (`console.anthropic.com`); las cuentas nuevas suelen recibir un crédito de prueba (importe variable, no es un tier gratuito permanente). Usar el modelo **Haiku** (el más barato) para que rinda. Con el modo offline, la caja funciona igualmente sin key.

## Criterios de aceptación (BDD)

```gherkin
# language: es
Característica: Ask the AI funcional

  Escenario: Modo offline (sin API key)
    Dado un matemático con una simulación completada y sin API key configurada
    Cuando pregunta a la IA sobre la simulación
    Entonces recibe una explicación derivada de las métricas (no un "no disponible" ni un 503)

  Escenario: Modo Claude (con API key)
    Dado ANTHROPIC_ENABLED=true y una API key válida
    Cuando pregunta a la IA
    Entonces la respuesta proviene de Claude

  Escenario: Error del proveedor
    Dado ANTHROPIC_ENABLED=true pero la llamada al proveedor falla
    Entonces la caja informa de indisponibilidad (503) sin romper el resto del dashboard
```

## Verificación INVEST

| Criterio | Cumplimiento |
|---|---|
| **I**ndependiente | Backend + config; la UI ya existe. |
| **N**egociable | El contenido exacto de la explicación offline es negociable. |
| **V**aliosa | La función deja de estar "muerta"; utilidad inmediata sin coste. |
| **E**stimable | Un `Explainer` offline + wiring de activación + tests. |
| **S**mall | Acotada al módulo de IA y a la configuración de despliegue. |
| **T**estable | Tests de modo offline, modo Claude (fake/IT) y degradación de errores. |

**Fuera de alcance:** *prompt caching* y coste/optimización de tokens (post-MVP); rediseño de la caja de preguntas.
