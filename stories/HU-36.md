# HU-36 — La API rechaza arrancar con secretos de despliegue débiles o de ejemplo

> **Como** equipo de plataforma,
> **quiero** que la aplicación no arranque si `JWT_SECRET` es débil o es el valor de ejemplo del repositorio,
> **para** no desplegar por error un demo público firmando sesiones con un secreto adivinable.

**Prioridad:** Should Have · **Estimación:** S · **Perfil:** Plataforma/DevOps

## Contexto y valor

`.env.example` trae `JWT_SECRET=admin`: un valor corto y trivial, pensado sólo como *placeholder*. Nada en el arranque de la aplicación impide que ese mismo valor (o cualquier otro de pocos caracteres) llegue a un despliegue real: si alguien copia `.env.example` a `.env` sin cambiarlo, el VPS público firmaría JWT con un secreto adivinable, permitiendo falsificar tokens de cualquier rol.

## Alcance

- Validar en el arranque (por ejemplo, en el proveedor de `JwtAuthFilter`/configuración de JWT) que `JWT_SECRET` tiene una longitud mínima razonable para HS256 (≥ 32 caracteres) y falla-rápido (excepción en el arranque) si no la cumple.
- Sustituir el `JWT_SECRET=admin` de `.env.example` por un *placeholder* que sea evidentemente no-productivo (p. ej. `JWT_SECRET=change-me-please-32-chars-min`) y documentar cómo generar uno fuerte (`openssl rand -base64 48`).

## Criterios de aceptación (BDD)

```gherkin
# language: es
Característica: Rechazo de secretos débiles al arrancar

  Escenario: Secreto demasiado corto
    Dado JWT_SECRET con menos del mínimo de caracteres exigido
    Cuando la aplicación arranca
    Entonces el arranque falla con un mensaje claro indicando el requisito de longitud

  Escenario: Secreto válido
    Dado un JWT_SECRET que cumple la longitud mínima
    Cuando la aplicación arranca
    Entonces arranca con normalidad

  Escenario: Documentación del secreto de ejemplo
    Dado .env.example
    Cuando alguien lo copia a .env sin cambiar JWT_SECRET
    Entonces el arranque falla (el placeholder no cumple la longitud mínima), evitando un despliegue accidental inseguro
```

## Verificación INVEST

| Criterio | Cumplimiento |
|---|---|
| **I**ndependiente | Una validación en el arranque + un cambio de documentación. |
| **N**egociable | El umbral exacto de longitud/entropía es negociable. |
| **V**aliosa | Convierte un error de configuración silencioso en un fallo de arranque explícito. |
| **E**stimable | Una validación + su test unitario. |
| **S**mall | Acotada a la configuración de JWT. |
| **T**estable | Test unitario con secreto corto (falla) y largo (arranca). |

**Fuera de alcance:** rotación de secretos, integración con un gestor de secretos (Vault, etc. — ya se inyectan por variables de entorno según HU-24).
